# Linked native proxy authoring

Linked coarse/fine objects remain protected by default. Preparing a family is an explicit, undoable operation after a read-only cost preview. Supported static families permit paired transforms, geometry replacement, material slots, owning Kit authoring, duplication/removal and existing rigid rest-bone edits through the validated transactions described below. Unknown skin, morph, gameplay ownership and declaration layouts remain guarded. Generated far roots cannot be moved directly.

## Native replacement and eligibility

The tool replaces a merged coarse SceneObject with render-only Model+Skeleton copies of every fine object, preserving every visual and each visual's lowest native mesh, matching face-group/palette level, immutable rigid bind, packed buffers and material GUIDs. Mesh ranges inherit the original coarse cutoff. The original native coarse parent, fine child and child-completer contract remain; no physics or gameplay components are copied.

Eligibility uses typed ownership and completeness, not archive names, stock GUIDs or frame-count constants. The native hierarchy must be valid, the parent must have one complete leaf child, every fine Model participant must belong to an active canonical scene, and the original coarse render-only root must be owned by an actual SceneCollection. Exactly one Model component per object is supported. Unknown participant representations, unresolved visual references, nested frame hierarchies, skinned/morph/correction-morph data, unsupported bind layouts and ambiguous coarse ranges refuse before native ID allocation. ABI/dependency validation is performed during inspection and repeated before preparation. A changed material dependency list invalidates the reviewed plan even if triangle/draw counts are unchanged.

Preparation is expensive. French block B changes **937 triangles / 1 draw** into **37,802 triangles / 235 draws** across 14 frames and 231 visuals. The scratch compressed far archive grew from 62,510 bytes to about 3.14 MB. Native SDS texture SlotVram changed from 69,632 to 3,254,640 bytes; conservative OtherRam reservations changed from 84,280 to 16,805,256 bytes. These are native wrapper reservations, not measured live memory. There is no automatic simplification, atlas bake or hidden preparation on ordinary editing.

## Persistence and transactions

Mapping is versioned toolkit workspace JSON under `resources/.illusion/linked-proxies/<parent-GUID>.json`, outside all SDS/GENR data. Version 2 records source/generated SceneObject GUID pairs, the destination GENR, physical resource/dependency hashes, original native LOD bounding-box baselines and material identity/texture-binding signatures. No new game field or resource type is invented. Reopening grants the transform capability only after native file hashes, complete family coverage, typed ownership, material signatures and group identities validate. Missing or stale mapping keeps the native render data readable and linked objects protected.

Global MTL texture and identity changes are also guarded: the material catalog protects referenced materials in both unsaved prepared documents and persisted mappings, even when their scene is unloaded. External absolute SDS documents are associated with the material workspace, not filtered out by archive path. Texture/sampler mutations, removal, rename and replacement under a protected hash refuse until preparation is undone and saved. Copies under a new, unrelated hash remain usable; parameter and flag changes preserve the dependency signature and remain editable. Automatic native texture carry refresh is not implemented.

Catalog save validates these signatures before writing any MTL, including material-only saves that never visit a scene document. Scene saves, transforms and reopening provide secondary checks. Persisted coverage is checked against the actual destination's SceneCollection roots and every native material face-group slot; removing an entry from JSON cannot remove its material protection. Null required fields and incomplete mappings refuse with warnings instead of changing baselines or crashing document load. Older mapping versions without material dependencies do not authorize writes.

Each source transform preflights all affected native world matrices and the complete bounds action before writing. Generated root world matrices match the fine source exactly. Source/generated writes and native parent/child bounds update atomically in memory. Existing native LOD graph and GPU membership identities remain stable. Original bounds baselines make move-back deterministic and prevent bounds creep. Protected geometry/rig fields, hierarchy containers, expected transforms and native bounds are pinned; a raw mutation refuses rather than becoming trusted through another transform. State acceptance is restricted to the states actually validated by that transaction.

Saving backs up affected extracted archive folders and mapping files in a workspace journal before native writes. Metadata and post-save snapshots are completed before the commit marker. An I/O failure restores native files, carry bookkeeping and dirty markers; an interrupted uncommitted journal is recovered before a new document parses any manifest. Undo after save restores the original native resources/manifests, removes only managed carried payloads and removes the newly created mapping. Redo retains the same native IDs and frame instances. This is process/interrupted-write recovery; no hardware power-loss guarantee is asserted.

That function unions transformed visual bounds into the runtime group. `CalculateAABB` (`0x1023F8800`) and `Synchronize` (`0x1023F8290`) repeat the group/child bounds update. The toolkit persists the corresponding typed 24-byte `m_WorldAABB` values and updates the stable editor graph. See [native LOD bounds](MAFIA3-NATIVE-LOD-BOUNDS.md).

- Non-stock Bridge A: 7 fine frames / 7 visuals. Downtown unique Bridge B: 1 fine frame / 6 visuals. Both pass preparation, paired move, save/reopen, compressed far-only geometry/attribute/buffer comparisons and exact undo. Ten additional nonempty district families pass strict inspection; unknown vegetation representations remain refused.
- Durable authoring probe: 15 checks cover read-only costs, duplicate/orphan Model rejection, stale material dependencies, paired translation/rotation/nonuniform scale, raw bounds refusal, both save-fault stages, moved-state reopen, missing mapping, exact file cleanup and interrupted-journal recovery before parsing.
- Durable material probe: 13 checks cover external and regular unsaved documents, persisted-only protection, identity/sampler refusal, unrelated material copies, actual parameter/flag saves, direct catalog bypass rejection before writes, null metadata, omitted signature coverage and complete cleanup. Host tests additionally exercise cross-editor undo refusal and material-only save preflight.
- Host/MCP tests cover native/GPU pairing, near/far visibility, explicit cost acceptance, save/build/fresh load, undo/redo, mixed-selection refusal and original tree/draw-order/pixel restoration.

All tests operate on copied files. No installed game assets are changed, and these checks do not claim an in-game playtest. The surveyed 608 fine frames have no native frame ancestors/children; hierarchy-bearing fine families remain refused rather than treated as verified transform support.

Assets entry points are `InspectLinkedProxyPreparation`, `PrepareLinkedProxyTransforms`, `ValidateLinkedProxyTransform` and `GetLinkedProxyTransformTargets`. Preparation changes document roots/meshes; the host refreshes only the replaced coarse subtree and new generated roots, preserving existing fine canonical objects and GPU instances.

## Count-preserving prepared geometry attributes (Source8)

This section records the historical Source8 attribute-only boundary, not the current capability matrix. The current static position/topology replacement and independent ownership path is documented in [paired geometry](MAFIA3-PAIRED-GEOMETRY.md); it supersedes the position/topology refusals below for supported layouts. The structural, material and rigid-skeleton transactions below supersede those historical refusals as well.

Prepared families now permit a narrowly scoped native attribute transaction through the ordinary compiled bridge binding. This does not authorize position, topology, material, hierarchy or rig changes. Static UV, normal and logical COLOR0 edits require original positions and corner/index/material topology exactly. Native XYZ remains bit-exact; the co-located tangent-handedness bit may change with the tangent frame.

Both source and counterpart must have exactly one native visual owner and unique editable MeshSet/vertex storage. Existing unknown declaration, sparse morph, skin, shared buffer and rebuild refusals remain. The writer checks every actual changed allocation bit against known UV/COLOR/normal/tangent channels, including bytes outside the selected vertex slice. No compression, face groups, culling or native group bounds may change.

For a higher fine LOD, every written storage field must be disjoint from native LOWEST and far storage. Selecting a higher LOD alone is insufficient, because the general writer can otherwise requantize shared compression. For LOWEST, matching native corner attributes are required, and near/far results are fully preflighted before applying either. Their write sets participate together in bridge conflict rejection. Scoped invariant pins accept only these validated storage writes. Save uses the existing recoverable native/mapping journal; no new game format fields are introduced.

`ApplyResult.AdditionalCompiledMeshes` contains preflighted far render output for the host's same-history GPU swaps. Apply/undo retains native near/far buffers and matching GPU replacements as one action. Multi-object batches preflight every native action and allocate their main/proxy GPU replacements before writing. Composite undo/redo preflights every paired action and transform before changing any child. The independent transforms, global material-dependency and structural guards remain active.

Copied French fixture acceptance covers UV/TBN, coherent authored normals, native BGRA colors, sub-quantum position/topology/material/ownership refusal, stale/conflicting results, higher-LOD isolation, fresh mapping reopen, compressed far-only geometry/TBN and complete resource/manifest undo. Durable entry points are `TestCompiledLinkedProxyGeometry` and the windowless `TestLinkedProxyGeometryHost`.

## Prepared structural, material and rigid-skeleton authoring

`CreatePreparedLinkedProxyGroup` creates an identity native Kit in the fine resource. A prepared fine leaf can be reparented under such a same-resource pure Kit, preserving normal local-transform semantics while its generated far object remains a standalone root with the matching world matrix. Duplication copies eligible render-only static leaves or whole pure-Kit subtrees, independently cloning owned geometry/cache identities and creating one generated far root per copied fine leaf. Removal detaches all matching native registrations and far roots together. Aggregate deletion refuses removal of the family's last pair before changing selection, history or GPU state. Skeleton helper rows are not separate native scene owners.

Material slot assignment first isolates native geometry ownership when needed. All fine LOD tables are validated; native LOWEST changes are mirrored to the corresponding far table. A new material can carry its actual native Texture/MemFile dependencies and wrapper reservations into each destination that uses it. A high-only assignment carries into the fine resource while leaving the far resource unchanged. Workspace version 2 optionally records `FineMaterialTextures`; its coverage is checked against actual hashed source GENR face-group tables, rather than trusting the JSON list. Global dependency protection therefore also covers materials used only by higher fine LODs. Material parameters/flags retain their existing dependency-preserving behavior.

Existing rigid rest bones can be inspected and edited with `InspectPreparedLinkedProxyBones` and `SetPreparedLinkedProxyBoneTransform`. The operation creates fresh near/far immutable skeleton GUIDs before changing authored matrices, retaining original definitions for other native users. It preserves bone indices, names, parent tables, inverse binds, palettes and raw vertex data. Both decoded geometries and native Model/group bounds update together. Only finite proper rigid matrices on static skeletons are accepted; verified static collision attachments follow the contract below, while morph, dynamic/gameplay and unverified skin combinations retain their guards. Stale Bone adapters cannot write an immutable skeleton that no longer belongs to their canonical frame.

Native parent-local semantics were checked directly in the copied symbolized executable. `VerifyMutableDataCreated` (`0x100426AE0`) passes immutable `m_OrigBoneMatrices` at offset `0x20` to `S_SkeletonDataMutable::Initialize` (`0x10205AAA0`), which copies each 48-byte matrix into the local runtime array. `C_SkeletonComponent::SkeletonUpdate` (`0x102055A80`) reads parent indices, composes that array along the parent chain, then produces model/world matrices. `C_SkeletonDataHelpers::AddBone` (`0x102053E70`) appends the supplied matrix to both authored and mutable local tables. The API consequently exposes parent-local row-vector transforms, not transient animation or model-space matrices.

Undo/redo preflight verifies the current canonical pair identities, native fields, material dependencies and owning hierarchy before any child mutation. Failed staging restores resource revisions, native LOD bounds revisions and exact cached rig adapters, including existing transient playback. Successful undo retains the same canonical frame identities. Copied-file durable entry points are `TestCompiledLinkedProxyStructure`, `TestCompiledLinkedProxyHighMaterials` and the unshown GPU/public-host `TestLinkedProxyStructureHost`; they cover native ownership, save/reopen, carried dependencies, stale table/DDS refusal, second-allocation faults, paired Kit visibility, public deletion and exact native/file/GPU restoration.

### Native rigid bone insertion and reparenting

`AddPreparedLinkedProxyBone` appends one unused bone to independently copied near/far skeletons. All five native tables grow together: original local matrices, inverse binds, parent IDs, joint-local envelopes and hashed names. Existing indices, inverse binds, palette slots, attachments and raw geometry are unchanged. The new bone receives a finite positive envelope and a valid model inverse bind. It remains unused until a separately supported binding operation assigns geometry or an attachment. Native limits retain indices0–254 and reserve255 as the root sentinel.

`ReparentPreparedLinkedProxyBone` changes an existing parent while preserving its model bind matrix. It permits an earlier parent index or a root; forward references/cycles refuse because native skeleton updating iterates parent-first. Both operations use the same native ownership/budget/bounds transaction as rest editing. They do not unlock unknown skinned/morph or dynamic/gameplay dependency rewriting.

The host now stages rebuilt skeleton rows, canonical rig inventory, picking anchors and overlay buffers before installation. Bone selection follows the native index across replacement trees; removing a newly appended selected bone on undo falls back to its canonical model. Undo restores the actual previous tree/adapters, not merely equivalent new rows. Overlay history retains its own COM references, so a later live-pose/transform overlay refresh cannot dispose recorded buffers. Manual visibility and ghost state survive GPU swaps after the row setter's own visibility synchronization. Generic property/gizmo writes still refuse prepared bones and cannot bypass paired authoring.

Copied French durable `TestPreparedProxyRigStructure` passes9 CPU checks; unshown `TestPreparedProxyRigHost` passes8 GPU/public-host checks, including a second-allocation failure, real added-bone pixels, selected accent/picking, native parent tree changes, exact native/cache/tree/GPU/image undo and canonical redo. No installed files or game process are involved.


### Static collision attachments during rigid rest editing

A pure Model/Skeleton owner may also carry one uniquely owned native `C_CollisionComponent`. Every volume must use a supported box, capsule, convex or triangle shape, an 88-byte placement record, a valid bone ID or frame sentinel65535, and a complete verified bone-helper map. Custom collision arrays, unknown fields, dynamic bodies and gameplay components refuse before mutation; static glass has the additional verified contract below. Native shape geometry, shape-local matrices, material/layer flags, helper order and all non-placement bytes stay unchanged.

Native `C_CollisionComponent::ActivateElement` (`0x101396AE0`) copies the serialized model-bind collision matrix directly into element creation. Its static component has no skeleton-update callback; the separate `C_DynamicComponent::BuildBoneInformation` (`0x10139A380`) is outside this supported contract. Each attached volume therefore receives `oldPlacement * inverse(oldBoneModel) * newBoneModel` exactly once. Frame-sentinel placements remain unchanged. Both the generated far rest skeleton and fine render geometry follow their existing paired transaction; collision remains owned by the fine object.

The host allocates before/after physical wireframe buffers before installing any native/GPU history state. Hidden-at-edit overlays can be enabled before undo without losing their geometry, and ordinary collision-free rig edits skip this extra work. `TestPreparedProxyRigCollision` passes5 copied-file CPU checks for exact placements, untouched metadata, independent reopen and byte-exact native/file undo. `TestPreparedProxyRigCollisionHost` passes3 unshown GPU checks for changed collision pixels and exact undo/redo, including the visibility transition. Skinned/morph and dynamic collision-aware rest authoring remain explicitly unsupported.

Such pure Model/Skeleton/CC/Glass owners now support paired rigid rest editing when every pane resolves to exactly one rigid visual and a matching collision attachment bone. The raw `DA7BCBE6` glass table is count-prefixed with28-byte records; bone ID is at20, runtime pane ID at8 and runtime flags at22. Copied native `C_GlassComponent::OnActivate` (`0x101AACE10`) registers CC helper elements by the pane's bone ID. `C_GlassBasePane::GetLocalPosition` (`0x101A9DA90`) obtains the current rigid visual from that bone and inverts its current world matrix. The unshown `TestPreparedProxyRigGlassHost` passes3 GPU checks for changed physical pane pixels and exact undo/redo, including enabling the overlay after the edit. This extends static Glass authoring; it does not enable DynamicComponent, morph dependencies or mixed skin/collision contracts. Verified pure weighted props use the separate contract below.


### Authored prepared weighted props

`ImportPreparedSkinnedProp` creates a genuine near/far native pair from an actual shared-library Model/Skeleton source. Its arguments identify the source resource/GUID, an existing fine family owner and a same-resource owning Kit. The near object is owned inline by that Kit and starts at the selected owner's world transform. Its immutable skeleton, every mesh level, vertex/index allocation and native cache identity are independently copied into the fine destination. The far destination receives an independently owned LOWEST closure, its matching face-group/palette level and the original family's coarse cutoff. No source template is mutated, no arbitrary group membership is invented, and generic deformation import remains protected.

The typed contract requires a pure Model/Skeleton leaf, resolved components, empty deletion/virtual/owning-skeleton dependencies, finite proper rigid parent-first rest/inverse matrices, one explicit four-weight stream per level and a complete local-to-global palette. Every displayed positive influence must name a valid bone, weights must sum to one, and every joint-local influenced vertex must lie inside its native immutable envelope at every level. Morph atlas/correction data, Dynamic/gameplay components, unknown ownership and incomplete envelopes refuse before placement. Eligibility has no stock GUID/name whitelist. The current copied CityCrash inventory exposes the five-bone filing cabinet; the stock banknote's LOWEST envelope is incomplete and correctly refuses.

The palette mapping follows native `C_ModelComponent::SetWorldMatrices` (`0x102000EA0`): palette slots select global skeleton bone IDs. Rest edits preserve raw vertex weights/indices, inverse binds and palette order while pairing all current model matrices. Local bounds are the union of joint envelopes transformed by current model matrices; normalized positive blending guarantees containment. Skeleton local/world and native group boxes update together. Existing unused-bone insertion and model-bind-preserving reparenting work through the same copied-immutable transaction.

Compiled authoring offers **Import verified weighted prop under selected Kit**, with an asynchronous read-only list of sources passing the complete contract. MCP exposes `linked_proxy_skin_sources` and `linked_proxy_import_skin`; existing rest-bone tools inspect/edit the result. Native/GPU staging finishes before any tree, selection or history installation. Fault rollback restores native revisions, cache adapters, bounds and wrapper staging. One canonical skeleton tree is installed per frame, avoiding duplicate skeletons under single-visual mesh rows.

`TestPreparedProxySkin` passes12 CPU checks: source inventory/refusal, native ownership, exact near/far geometry and influences, paired rest matrices, deformed-vertex envelope containment, insertion/reparenting, independent mapping reopen, compressed far-only decoding and exact source/working-file undo. `TestPreparedProxySkinHost` passes10 unshown GPU/host checks, including second-allocation failure, canonical five-bone rows, actual weighted near pixels, native far visibility, exact pixel undo/redo and complete native/tree/GPU/file restoration. The previous rigid host8 checks also pass after canonical tree grouping.

Read-only `illusion_memory.json` caches were initialized from copied original SDS before the exact baseline. No installed files, desktop input or game process were used.
